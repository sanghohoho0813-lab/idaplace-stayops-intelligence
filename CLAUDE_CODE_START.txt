이번 프로젝트는 (주)이다플레이스의 `StayOps Intelligence` AX+플랫폼 인터랙티브 MVP 개발이다.
GitHub 저장소 권장명: `idaplace-stayops-intelligence` (Private).
목표: 2026년 10월 27일(화) 대표 미팅에서 직접 클릭할 수 있는 실제 작동형 고품질 시연 제품 완성.

1. docs 폴더의 최신 통합 Master v4.1 전문과 이다플레이스 전용 개발 프롬프트 MD를 처음부터 끝까지 실제로 읽어라.
   - docs/(AX+플랫폼전용)미래AI랩_AX_Platform_Unified_Design_Development_System_v4.1_260922.md
   - docs/이다플레이스_ClaudeCode_AX플랫폼_MVP_통합프롬프트_261023.md
2. docs/references의 AX프론트 시안은 디자인 기준으로, 필스토리 화면은 기능 연구용으로만 참고하라. 경쟁사 UI를 복제하지 말라.
3. 현재 사업 단계: 이다컴퍼니는 숙박시설 공사/개업 준비 중이고 아직 실제 운영·매출이 확인되지 않았다. 이다플레이스는 AX 소프트웨어 기술개발·공급 주체로 육성할 계획이다. 실데이터/실API/실도어락을 연결한 척하지 마라.
4. P0 시연 흐름 두 가지를 실제 작동하게 구현하라.
   A. 개업 준비 작업 → 모바일 직원 완료 → PC 진행률/알림/로그 즉시 반영.
   B. 명확한 FUTURE OPERATIONS DEMO → 샘플 예약 → QR 체크인 → 안전한 예약 확인 → Demo 도어락 PIN 발급 → 가상 체크아웃 → 청소업무 생성 → 완료 → 객실상태/Proof Event 반영.
5. 임시 PIN은 DemoAccessProvider만 사용한다. 실제 스마트 도어락 제어는 절대 구현된 척하지 말고, 공식 API 승인과 실물 검증 뒤 별도 진행한다. 불명확한 경우 LIVE_LOCK_ENABLED=false를 유지한다.
6. PC / Mobile / PC+Mobile 3모드는 Master v4.1의 동일 Route/Data/State 및 실제 390px 모바일 렌더링 규칙을 따른다. Canonical 7 Theme/Grouped Sidebar/실증 Proof Event/Role/Why AX/Presentation Mode/QA를 적용한다.
7. 기능이 많은 척하는 껍데기 대신, 모든 P0 버튼·폼·데이터 흐름을 실제로 동작시키고 데모 리셋과 운영 장애 시나리오 1개도 완성하라.
8. 마무리 시 DEMO_SCRIPT.md, QA_REPORT.md, PROJECT_STATE.md, EVIDENCE_PLAN.md, INTEGRATION_READINESS.md를 생성하고 실행 방법과 실패/미구현 사실을 정확히 정리하라.

작업을 멈춰 놓고 계획만 발표하지 말고 현재 저장소를 확인한 후 구현을 진행하라. 첫 Build부터 70~80% 수준의 시연 완성도를 지향하되 안정적인 P0 폐회로(Closed Loop)를 최우선으로 하라.
